# 智慧家居上云项目 PPT 制作说明文档

本文档用于帮助没有看过代码的人快速制作项目展示 PPT。内容覆盖 App、华为云 IoTDA、硬件板子、LCD 显示、智能助手、设备控制闭环和技术栈。

建议 PPT 页数：12 到 16 页。  
建议展示时间：5 到 10 分钟。  
项目关键词：智慧家居、HarmonyOS、华为云 IoTDA、OpenHarmony、RK2206、MQTT、设备控制、LCD 场景显示。

## 1. 项目一句话介绍

本项目是一个“智慧家居上云控制系统”。用户可以在 HarmonyOS App 中点击设备按钮或通过智能助手输入指令，App 将控制命令发送到华为云 IoTDA，华为云再把命令下发给 RK2206 开发板，开发板收到命令后控制电机、灯光和 LCD 屏幕，实现 App、云平台、硬件设备的完整联动。

可以在 PPT 中这样描述：

> 我们做的是一个智慧家居控制系统，核心目标是让手机 App 能真正控制硬件设备。用户在 App 上打开空调、关闭窗帘、启动扫地机器人或切换场景时，命令会通过华为云下发到开发板，开发板执行电机和灯光动作，同时在 LCD 屏幕上显示对应状态或场景图片。

## 2. 项目整体架构

PPT 可以画成下面这条链路：

```text
用户操作
  ↓
HarmonyOS 智慧家居 App
  ↓
HuaweiCloudApi.ets
  ↓
华为云 IAM 鉴权
  ↓
华为云 IoTDA 设备命令下发
  ↓
RK2206 开发板 MQTT 接收
  ↓
C 语言解析命令
  ↓
控制电机 / 紫光灯 / LCD 屏幕
```

### 每一层的作用

| 层级 | 作用 | 主要技术 |
| --- | --- | --- |
| App 层 | 提供用户界面、设备按钮、智能助手、场景入口 | HarmonyOS、ArkTS、ArkUI |
| 云接口层 | 获取 IAM Token，向 IoTDA 下发命令 | ArkTS、HTTP、REST API |
| 华为云层 | 设备接入、命令转发、设备影子状态查看 | Huawei Cloud IAM、IoTDA |
| 板端通信层 | Wi-Fi 联网，MQTT 连接云平台 | OpenHarmony、MQTT、Paho MQTT |
| 板端执行层 | 解析命令，控制硬件动作 | C、cJSON、GPIO、LCD 驱动 |
| 硬件展示层 | 电机转动、灯光开关、LCD 图片和文字显示 | RK2206、LCD、传感器、电机 |

## 4. 华为云产品模型说明

当前板子端已经确认只稳定支持两个命令：

| 服务 ID | 命令名称 | 参数名 | 参数值 | 实际效果 |
| --- | --- | --- | --- | --- |
| `智慧农业` | `电机控制` | `Motor` | `ON` | 电机打开 |
| `智慧农业` | `电机控制` | `Motor` | `OFF` | 电机关闭 |
| `智慧农业` | `紫光灯控制` | `Light` | `ON` | 灯光打开，同时 LCD 显示早安场景 |
| `智慧农业` | `紫光灯控制` | `Light` | `OFF` | 灯光关闭，同时 LCD 显示回家场景 |

注意：虽然 App 中有空调、窗帘、扫地机器人、灯光等多个家居设备，但板端实际只认识 `Motor ON/OFF` 和 `Light ON/OFF`。所以本项目采用“App 侧语义映射”的方式，把不同家居设备的动作映射到板端支持的两个命令。

## 5. App 端功能说明和使用方法

### 5.1 首页空间化控制

功能说明：

首页是智慧家居的主控制台。用户可以看到客厅、卧室等空间，也可以看到空调、窗帘、灯光、扫地机器人、电视、空气净化器等设备点位。

使用方法：

1. 打开 App。
2. 进入首页。
3. 点击房间图上的设备悬浮点。
4. 进入设备详情或直接触发设备开关。
5. 如果该设备已经接入硬件映射，App 会通过华为云向板子下发命令。

PPT 展示建议：

- 放一张首页截图。
- 用箭头标出“设备悬浮点”。
- 说明用户不是在一个列表里找设备，而是在家的空间图上直接操作设备。

### 5.2 空调控制

功能说明：

App 中的空调开关被映射为板子的电机开关。用户点击打开空调时，App 下发 `Motor=ON`；用户点击关闭空调时，App 下发 `Motor=OFF`。

使用方法：

1. 在首页找到空调点位。
2. 点击空调按钮或进入空调详情页。
3. 点击开关按钮。
4. 打开空调时，板子串口应显示 `Motor On`。
5. 关闭空调时，板子串口应显示 `Motor Off`。

命令映射：

```text
打开空调 -> Motor=ON -> 电机打开
关闭空调 -> Motor=OFF -> 电机关闭
```

PPT 展示建议：

- 一页展示 App 空调按钮。
- 一页展示串口日志 `recv data ... Motor:ON`。
- 一页展示电机实际转动。

### 5.3 窗帘控制

功能说明：

窗帘也使用电机模拟，但窗帘的动作方向和空调不同。当前逻辑中：

```text
打开窗帘 -> Motor=OFF
关闭窗帘 -> Motor=ON
```

这样做是为了让界面中的“开窗帘/关窗帘”和实际电机表现保持一致。

使用方法：

1. 在首页点击窗帘悬浮点。
2. 进入窗帘详情或直接点击开关。
3. 点击“打开窗帘”，板子收到 `Motor=OFF`。
4. 点击“关闭窗帘”，板子收到 `Motor=ON`。

PPT 展示建议：

- 解释这里不是 bug，而是针对硬件方向做了反向映射。
- 强调 App 中每个设备可以有自己的命令映射规则。

### 5.4 扫地机器人控制

功能说明：

板子没有单独的扫地机器人命令，所以扫地机器人也通过电机模拟。为了让它更像“短时间工作一下”，App 侧会控制电机转动一段时间后自动关闭。

当前逻辑：

```text
启动扫地机器人 -> Motor=ON -> 延时约 3 秒 -> Motor=OFF
暂停扫地机器人 -> Motor=ON -> 延时约 1 秒 -> Motor=OFF
```

使用方法：

1. 在首页找到扫地机器人点位。
2. 点击开始。
3. 电机会转动一小段时间，然后自动停止。
4. 点击暂停。
5. 电机会短暂转动约 1 秒，然后停止。

PPT 展示建议：

- 说明板端只认识 `ON/OFF`，所以定时逻辑放在 App 端。
- 这体现了“用最小硬件命令实现更多家居语义”的思路。

### 5.5 灯光和场景图片

功能说明：

灯光使用华为云产品模型中的 `Light ON/OFF`。当前项目把灯光开关和 LCD 场景图片联动起来：

```text
Light=ON  -> LCD 显示早安场景图片
Light=OFF -> LCD 显示回家场景图片
```

使用方法：

1. 在 App 中点击灯光开关或场景按钮。
2. App 下发 `Light=ON/OFF`。
3. 板子收到命令后控制灯光。
4. LCD 屏幕切换到对应图片。

PPT 展示建议：

- 放两张 LCD 场景图。
- 一张写“早安场景”，一张写“回家场景”。
- 说明图片不是在线加载，而是转换成 RGB565 数组后编译到固件里。

### 5.6 智能助手控制

功能说明：

智能助手支持两类输入：

1. 普通问题：转发给 DeepSeek，返回普通聊天回答。
2. 家居控制指令：本地解析，不依赖 DeepSeek，直接控制设备。

示例指令：

```text
turn on the ac
turn off the ac
打开空调
关闭空调
打开灯
关闭灯
start robot
pause robot
open curtain
close curtain
```

执行效果：

```text
turn on the ac -> 空调已打开 -> Motor=ON
turn off the ac -> 空调已关闭 -> Motor=OFF
open curtain -> 窗帘已打开 -> Motor=OFF
close curtain -> 窗帘已关闭 -> Motor=ON
```

PPT 展示建议：

- 展示智能助手输入框。
- 展示输入 `turn on the ac`。
- 展示回复“空调已打开”。
- 展示串口收到 `Motor ON`。

### 5.7 华为云设备状态查看

功能说明：

板子会周期性上报环境数据和设备状态，华为云 IoTDA 中可以看到设备在线状态和设备影子数据。

可展示的数据：

- 温度
- 湿度
- 光照
- 电机状态
- 紫光灯状态
- 设备在线状态

使用方法：

1. 登录华为云控制台。
2. 进入 IoTDA 设备接入服务。
3. 找到对应产品和设备。
4. 查看设备是否在线。
5. 查看设备影子或属性上报数据。
6. App 也可以通过 `getDeviceData()` 读取设备影子。

PPT 展示建议：

- 放华为云设备在线截图。
- 放设备影子截图。
- 说明“这证明板子已经接入云端，状态可以被云平台看到”。

## 6. 板端功能说明

### 6.1 Wi-Fi 联网

板子启动后会连接指定 Wi-Fi。串口中可以看到类似信息：

```text
SetWifiModeOn begin
ConnectTo (...) done
network IP (...)
```

这说明板子已经连上网络。

### 6.2 MQTT 连接华为云

板子通过 MQTT 连接华为云 IoTDA。串口中可以看到类似信息：

```text
begin MQTT init
NetworkConnect ... success
oc package initialize success
```

这说明板子已经和华为云建立连接，可以接收命令。

### 6.3 传感器数据上报

板子周期性读取环境数据并上报：

```text
Luminance:820.00 temperature:25.70 humidity:50.68
```

这些数据可以在华为云设备影子中看到。

### 6.4 命令接收和解析

华为云下发命令后，串口会打印原始 JSON：

```text
recv data is {"paras":{"Motor":"ON"},"service_id":"智慧农业","command_name":"电机控制"}
Motor On
```

这说明：

1. App 命令已经到华为云。
2. 华为云已经把命令下发给板子。
3. 板子已经解析出 `Motor=ON`。
4. 板子已经执行电机打开动作。

### 6.5 LCD 显示

LCD 当前承担两个作用：

1. 启动时显示 `Smart Home` 和 `Cloud Ready`。
2. 收到不同命令时显示状态文字或场景图片。

当前显示逻辑：

```text
Light=ON  -> 显示早安图片 + Good Morning
Light=OFF -> 显示回家图片 + Welcome Home
Motor=ON  -> 保留当前背景，叠加 Air ON / Motor ON
Motor=OFF -> 保留当前背景，叠加 Air OFF / Motor OFF
```

这样可以避免电机开关后把场景图片和文字覆盖乱掉。

## 7. App 到硬件的完整命令闭环

可以在 PPT 中重点展示这个闭环：

```text
用户点击 App 空调开关
  ↓
App 调用 sendMotorCommand("ON")
  ↓
App 获取华为云 IAM Token
  ↓
App 请求 IoTDA 命令下发接口
  ↓
华为云把命令发给设备
  ↓
板子 MQTT 收到 JSON 命令
  ↓
cJSON 解析 command_name 和 paras
  ↓
识别 Motor=ON
  ↓
GPIO 控制电机打开
  ↓
LCD 显示 Air ON / Motor ON
```

一句话解释：

> 这个项目不是只做了 App 界面，而是从 App 到云平台再到真实硬件形成了完整闭环。

## 13. 答辩时可以这样讲

### 如果老师问：为什么项目叫智慧家居，但华为云产品模型是智慧农业？

可以回答：

> 最开始使用的是智慧农业上云实验模板，里面已经有温湿度、光照、电机和紫光灯这些基础能力。我们在这个基础上进行了改造，把电机和灯光能力映射到智慧家居场景中，例如空调、窗帘、扫地机器人和灯光控制。因此底层产品模型仍然叫“智慧农业”，但上层 App 和演示场景已经扩展成智慧家居。

### 如果老师问：为什么多个设备都用电机控制？

可以回答：

> 因为当前板端稳定支持的命令只有 `Motor ON/OFF` 和 `Light ON/OFF`。为了完成最小可用闭环，我们把更多家居语义放在 App 侧处理。比如空调开关直接映射电机开关，扫地机器人通过电机短时间转动模拟，窗帘通过反向映射模拟开合。这种方式可以在不大改板端产品模型的情况下快速完成真实硬件演示。

### 如果老师问：为什么智能助手不全部交给 DeepSeek？

可以回答：

> 普通聊天可以交给 DeepSeek，但设备控制需要稳定和低延迟。如果每次控制设备都依赖大模型，网络或 API Key 出问题就无法控制设备。所以我们采用混合方案：普通问题走 DeepSeek，家居控制指令走本地解析，然后直接下发华为云命令。

### 如果老师问：LCD 图片是怎么显示的？

可以回答：

> 我们先把场景图片转换成适合 LCD 的 RGB565 数据数组，然后把数组编译进板端固件。板子收到 `Light ON/OFF` 命令时，调用 LCD 驱动显示不同数组对应的图片，再叠加状态文字。

### 如果老师问：如何证明不是 App 假控制？

可以回答：

> 可以从三个地方证明。第一，华为云设备页面能看到设备在线和状态上报。第二，串口日志能看到板子收到的原始 JSON 命令。第三，电机和 LCD 会产生实际硬件动作。这说明命令不是停留在 App 页面，而是到达了真实硬件。

## 14. 最终演示话术模板

可以直接照着下面这段讲：

> 大家好，我的项目是一个基于 HarmonyOS 和华为云 IoTDA 的智慧家居上云控制系统。这个系统由三部分组成：第一部分是 HarmonyOS App，负责用户交互和智能助手；第二部分是华为云 IoTDA，负责设备接入、设备影子和命令下发；第三部分是 RK2206 开发板，负责接收云端命令并控制电机、灯光和 LCD 屏幕。
>
> 在 App 中，用户可以点击空调、窗帘、灯光、扫地机器人等设备，也可以在智能助手中输入指令。App 会先通过 IAM 获取华为云 Token，然后调用 IoTDA 的命令下发接口。板子通过 MQTT 接收命令，使用 cJSON 解析 JSON 数据，最后控制 GPIO 和 LCD。
>
> 当前板子端稳定支持两个命令：`Motor ON/OFF` 和 `Light ON/OFF`。我们在 App 侧做了设备语义映射，比如空调开关映射到电机开关，窗帘做反向电机映射，扫地机器人通过电机定时转动模拟，灯光控制则联动 LCD 场景图片。
>
> 这个项目的亮点是完成了 App、云平台和真实硬件的闭环，不只是页面原型。通过串口日志、华为云设备影子和硬件动作，都可以证明命令已经从 App 到达板子并被执行。

## 15. 制作 PPT 时的注意事项

1. 不要在 PPT 中放真实密码、IAM 密码、API Key。
2. 可以展示设备 ID，但敏感密钥建议打码。
3. PPT 中要突出“完整闭环”，不要只讲 App 页面。
4. 每个技术名词都用一句话解释，避免听众听不懂。
5. 演示时先打开串口，方便证明板子收到命令。
6. 如果 DeepSeek 网络不稳定，就重点演示本地智能家居指令解析。
7. 如果现场网络不稳定，提前准备录屏或截图作为备用。
8. 展示 LCD 时尽量拍清楚图片和文字，说明它和 App 场景有关联。
